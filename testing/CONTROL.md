## 1. Hypotheses
Stated 2026-11-02, before any arm B or judge data, in Garrett's words:
- **H1:** A finds more judge-confirmed findings per hour than B.
- **H2:** A has fewer judge-refuted claims per finding than B.
- **H0, the null** (added 2026-11-02, before any arm B or judge data, in Garrett's words): the arms don't differ beyond the noise floor (§12.1).

Three repos are the first checkpoint, described only; the test is at five, and no claim of significance comes before it (§14).

## 4. The output form
Both arms write their findings this way (arm A in a file of its own, §5), and the judge's claims file keeps it:

```
# Findings

## 1: <title: what the user loses, in plain words>
Severity: <data-loss | security | wrong-result | crash | stuck | process | cosmetic>
Where: <path>:<line>, at <short sha> (more than one place: comma-separated)
What the user loses: <one or two sentences>
Steps:
1. <step>
2. <step>
Expected: <what should happen>
Actual: <what happens>
Evidence: reading
```

or `Evidence: probe`, then the probe's output, verbatim, in a code block. Findings are numbered worst first, one bug each, and each stands alone: no reference to another finding by its number. The rest of a report comes after, under its own top-level headings (`# Not reached`, ...).

**Severity** is the worst real consequence, on the ledger's scale, explained the same way to arm B and the judge:
- `data-loss`: something the user entered or saved is lost, overwritten or changed without their say;
- `security`: someone can see or change what they shouldn't, or a secret is exposed;
- `wrong-result`: the app shows or stores a wrong value (a balance, a total, a date), with nothing lost;
- `crash`: an error or a failed request where the app should work;
- `stuck`: the user can't finish, retry or undo something, or a job never ends;
- `process`: a gap in how the code is built or checked (tests, migrations, configuration) that no user feels yet;
- `cosmetic`: looks or reads wrong; nothing lost or wrong.

## 11. tools/control.py
Standard-library Python. It reads and writes only the files named on its command line and runs nothing from a reviewed repo. Checked on 2026-11-02 against dummy files (three findings, a code fence holding `#` lines, a finding that names a ledger id and the reviewer, a cross-arm duplicate, both override flags, malformed tables) and against transcripts on this machine: monize's arm A, its parent session, and a session that loaded a nested `CLAUDE.md`. Since 2026-11-03 each command also has a hand-worked example in Dev Instincts' own tests (`tests/test_control.py`, run by `tools/check.sh`).

- **shuffle:** `python -I tools/control.py shuffle --run A1 <file> --run B1 <file> --out claims.md --key key.json`, and on the first repo also `--run A2 <file> --run B2 <file>`: each run's findings file with its run, two runs or four; any other set is refused. Takes the `## <id>: <title>` blocks under `# Findings` in each file (the whole file if it has no such heading; `#` lines inside code fences don't count). Refuses, writing nothing, if a finding still holds a Dev Instincts term, a ledger-style id, `dev-control`, or a pointer to another finding by its number (`finding 2`, `findings 1 and 3`, `finding #2`; an issue's `#12` passes) (§4; §13, step 5). Gives each finding a two-letter code (consonants only, no B), shuffles them, rewrites each `Severity:` line to the scale's word, and writes `claims.md` without the runs' ids. The seed is the SHA-256 of a fixed tag and every run's label and file, in label order: nobody picks it, and a re-run on the same files, the flags in any order, writes the same `claims.md`. The key holds the seed, the SHA-256 of each input and of `claims.md`, and each code's arm, run, own id, severity and evidence type. Run it once; its printed hashes go in `metrics/CONTROL.md`.
- **agreement:** `python -I tools/control.py agreement key.json judge-1.md judge-2.md --claims claims.md --out claims-3.md`. Prints the agreement rate (§12.2) to two decimals with its count, and the disputed codes in `claims.md`'s order. Writes `claims-3.md`: `claims.md`'s header and the disputed claims, word for word and in its order; with none disputed it writes nothing, as there is no run 3 (§10.1). Refuses a `claims.md` whose SHA-256 isn't the key's.
- **final:** `python -I tools/control.py final key.json judge-1.md judge-2.md [judge-3.md] --out verdicts.md`. Writes the final `verdicts.md` in §10's form, one row per claim in `claims.md`'s order (§12.2): an agreed claim's verdict and severity, a disputed one's from run 3, the Evidence cell saying which (`runs 1 and 2 agree`, or `run 3;` and what runs 1 and 2 said); the groups joined across the runs, numbered by each group's first claim; and in its notes the inputs and their SHA-256s. Refuses a disputed claim without `judge-3.md`, and a `judge-3.md` that rules on a claim runs 1 and 2 agree on.
- **score:** `python -I tools/control.py score key.json verdicts.md --minutes A1=<m> B1=<m> [--not-a-bug CODE] [--accepted CODE]`, on the first repo with `A2=<m> B2=<m>` too: each run's time used, one value for each run in the key. Refuses a table that misses a code, repeats one, or holds a verdict, group or severity it can't read; maps the codes back to the runs; prints §12's measures for each run on its own, and the groups. Then the headline measures (§12.1): with four runs, each arm's within-arm difference, the floor, each arm's mean, the gap A − B and its reading, `no difference`, `A's way` or `B's way`; with two, the gap, to be read against the first repo's floor. `--not-a-bug CODE`: a maintainer rejected the filed issue for that claim's group as not a bug. `--accepted CODE`: that group's filed issue was acknowledged or fixed upstream.
- **session:** `python -I tools/control.py session <transcript.jsonl> [--clone DIR] [--report FILE] [--leak] [--term TEXT] [--prompt FILE]`. From one Claude Code transcript: the version; the model, requested model and effort of every request; the permission mode; the first prompt's time, the clone's creation and the report's last write; time used; tokens; the tools used; the context Claude Code attached, by type, and any `CLAUDE.md` or `AGENTS.md` it loaded. With `--leak`, every place a Dev Instincts term (`instinct`, `findings.jsonl`, `FILING.md`, `STATS.md`, `agent-memory`, `agents-parked`) or a ledger-style id (`MZ-L01`) appears anywhere in the transcript, the context Claude Code sent included; `--term` adds a text to look for. `--prompt FILE`: the SHA-256 of the transcript's first prompt, and whether the prompt file's text matches it (§11.1, §13.1); a `prompt wrapper` line before them says whether it stripped a paste's wrapper first (§16, item 16).
A session's transcript is `~/.claude/projects/<folder>/<session id>.jsonl`; a subagent's is `~/.claude/projects/<folder>/<parent session id>/subagents/agent-<id>.jsonl`.

## 12. Measures
Per arm, per repo, fixed before data:
- **Findings:** the arm's entries under `# Findings`.
- **Proven share:** findings whose evidence is a probe's output (`Evidence: probe`), over findings.
- **Confirmed:** distinct bugs, that is the judge's groups holding at least one of the arm's findings marked confirmed. A bug the arm lists twice counts once.
- **Refuted:** the arm's findings marked refuted. Each is a wrong claim, so a wrong claim listed twice counts twice.
- **Can't tell:** the arm's findings marked can't tell.
- **Unique to the arm:** its confirmed groups in which the other arm has no confirmed finding.
- **Overlap:** the groups confirmed for both arms (one number per repo).
- **Severity-weighted confirmed:** the sum, over the arm's confirmed groups, of the weight of the judge's severity (the highest, if the judge graded the arm's findings in one group differently). The weights, fixed before data: data-loss 4, security 4, wrong-result 3, crash 3, stuck 2, process 1, cosmetic 1.
- **Accepted upstream:** the arm's confirmed groups whose filed issue reached `acknowledged` or `fixed` in `metrics/FILED.md` (FILING §7). A group both arms found counts for both.
- **Time used:** minutes from the later of the first prompt and the clone's creation, to the report file's last write, by `tools/control.py session`: the prompt's time from the transcript, the clone's and the report's from their file times, read right after the run. Arm A's report is its round report, `reviews/<repo>/<round>.md`; arm B's is `report.md`.
- **Tokens:** output and input tokens, summed from the session's transcript, each request once (§11). Claude Code's own figures aren't used: a subagent's completion notice gives its context size, and `/cost` depends on the plan, so the two arms' numbers wouldn't count the same thing.
- **Headline:** confirmed per hour (confirmed ÷ time used in hours), for H1; refuted per finding (refuted ÷ findings), for H2.
- **Maintainers have the last word.** What they say about a filed issue is the final truth and overrides the judge. An issue rejected as not a bug turns its group's confirmed findings into refuted, for both arms (`--not-a-bug`). A rejection for another reason (a duplicate, won't fix) leaves the verdict and counts no acceptance; `silent` leaves the verdict. Each change is dated in `metrics/CONTROL.md`, with the issue, and the row is scored again.

### 12.1 Repeats and the noise floor
Garrett's decision (2026-11-02): on the first repo both arms run twice (§5.1, §7.1). The within-arm difference is the noise floor; a between-arm gap smaller than it is reported as no difference. Worked out this way (the architect's, 2026-11-02; Garrett may change it before the next control run):
- On the first repo each run is scored on its own, against the final verdicts (§12.2): its findings, its confirmed groups, its time used.
- For each headline measure (confirmed per hour, refuted per finding), an arm's **within-arm difference** is the size of the gap between its two runs, and **the noise floor** is the larger of arm A's and arm B's.
- **The between-arm gap** is arm A's value minus arm B's, where an arm's value is its one run's, or on the first repo the mean of its two.
- A gap whose size is under the floor is **no difference** for that repo and measure; at or over it, its sign is the repo's direction (§14). The first repo's floor serves every repo, in the measure's own units.
- Cost: one more run of each arm on the first repo, each up to the 2 hour box, with its session check and transcript.

- **Agreement rate:** the claims they agree on, over all claims; recorded with the repo's row in `metrics/CONTROL.md`.
