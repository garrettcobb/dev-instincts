Check a set of bug claims about kenlasko/monize, an open-source personal finance web app (TypeScript: a Next.js and React front end; a NestJS, TypeORM and PostgreSQL back end). Its main branch at commit 93f4e68 is checked out, read only, in the folder repo here. The claims are in claims.md here. Each has a two-letter code, and their order is random. They come from more than one review. Don't try to work out which review wrote which claim, and don't look for anything else written about this repo.

For every claim, read the code it points to and decide:
- confirmed: the code at 93f4e68 has the defect the claim describes, and it happens the way the claim's steps say, or by another path you name. Its consequence may be smaller or larger than claimed.
- refuted: the code doesn't have that defect: it handles the case, or a step can't happen.
- can't tell: reading the code doesn't settle it, for example because it would take running the app, its database or another service.

Give your own evidence for every verdict: the file:line at 93f4e68 and what those lines do, in a sentence or two. Don't take a claim's word or its program output for it: check the code. Where running code would settle a claim, you may write a small program under the rules below.

For each confirmed claim, give the severity you see in the code, as the worst real consequence:
- data-loss: something the user entered or saved is lost, overwritten or changed without their say;
- security: someone can see or change what they shouldn't, or a secret is exposed;
- wrong-result: the app shows or stores a wrong value (a balance, a total, a date), with nothing lost;
- crash: an error or a failed request where the app should work;
- stuck: the user can't finish, retry or undo something, or a job never ends;
- process: a gap in how the code is built or checked (tests, migrations, configuration) that no user feels yet;
- cosmetic: looks or reads wrong; nothing lost or wrong.

Group the claims: claims with the same cause in the same place are one group. Number the groups 1, 2, 3 and so on; a claim with no duplicate is a group of its own. Every claim still gets its own verdict.
