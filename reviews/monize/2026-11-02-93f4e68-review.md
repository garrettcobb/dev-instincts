## 2. Findings, worst first

**MZ-L01, deleting an unused category silently deletes payroll deduction rules and blanks budget lines and loan category links.** data-loss, reading. `backend/src/categories/categories.service.ts:579-651` refuses only on `getTransactionCount` (654-698), which counts transactions, splits, schedules and schedule splits. The schema also points `payroll_deduction_rules` (CASCADE, `schema.sql:3640`), `budget_categories` and `budget_period_categories` (SET NULL, 2424, 2472), the loan columns on `accounts` (SET NULL, 1197-1207), `scheduled_transaction_overrides` (1222) and `shared_postings` (4722) at categories. In the app: make a category, add it to a budget and a payroll rule, delete it; the rule is gone and the budget line reads "Uncategorized". Fix: count every referencing table, inside the deleting transaction, and refuse with the breakdown. Instincts 6, 27.

**MZ-L02, the reconciled date is stamped with the server's day.** wrong-result, reproduced. `transaction-reconciliation.service.ts:167` writes `formatDateYMDLocal(new Date())` (server day; UTC in the containers) while line 172 decides future-dated by the user's day via `todayYMD()`. Probe (`probes/probe_reconciled_date.js`, `TZ=UTC node`): Toronto at 21:30 stamps tomorrow, Tokyo at 07:30 stamps yesterday, 3 of 3 cases off. In the app: user timezone Asia/Tokyo, reconcile a row dated today at 07:30; the panel says reconciled through yesterday. Fix: `todayYMD()`. Instincts 23, 11.

**MZ-L03, undo and import recompute the balance by the database's day.** wrong-result, reading. `action-history.service.ts:2111` and `import-post-processing.service.ts:81` bound the ledger with `CURRENT_DATE`; `accounts.service.ts:1751` and every delta path use the user's day. The undo path's comment (2106) says it uses "the same recalculation logic as AccountsService". In the app: Toronto user at 21:00 enters a row dated tomorrow (excluded), deletes another row and undoes it: the balance now includes tomorrow's row and stays wrong through later edits. Fix: pass the user's day as the bound, or call `recalculateCurrentBalance`. Instincts 23, 27.

**MZ-L04, reassigning a category fails past about 65,000 transactions.** crash, reading. `categories.service.ts:721-741` selects every transaction id of the user and binds them into `IN (:...transactionIds)`; the PostgreSQL Bind message carries a 16-bit parameter count. The category then can't be emptied or deleted. Fix: a join on `user_id` instead of the id list. Instinct 13.

**MZ-L05, payee delete has no referencer check on any door.** stuck, reading, not filed (§4). `payees.service.ts:1280-1308`; FKs without ON DELETE at `schema.sql:385`, `1084`; the filter maps 23503 to a generic 400 (`http-error-body.ts:125`). Same on the AI batch action and the MCP tool. Fix: count and refuse with a pointer to Merge. Instincts 17, 6.

**MZ-L06, category delete counts in one transaction and deletes in another.** wrong-result, reading, carried in L01's Related line. `categories.service.ts:600-608` vs `630-641`; `transactions.category_id` is SET NULL (`schema.sql:387`). Instinct 3.

**MZ-L07, import moves the balance for VOID and future rows, repaired afterwards.** process, reading, ledger only. `import-regular-processor.service.ts:154`; the repair at `import-post-processing.service.ts:44-112` logs when it fails. Instincts 6, 25.
