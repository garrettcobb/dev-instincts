## 6. Surprises
1. **Reviewers mutate the code, and the PRs where that found a gap shipped regressions anyway.** 68 inline comments in 55 PRs match the phrasing "nothing fails when I remove this" or "I can change this without test failures". That is a keyword count; I didn't read each one. In four cases a regression later shipped in exactly that code:
   - PR 19507 led to #36447 (DJ-006 to DJ-058);
   - PR 20009 led to #37311 and #37377 (DJ-020 to DJ-049, DJ-053);
   - PR 22039, where the reviewer flagged a whitespace behaviour change, led to #37450 (DJ-023 to DJ-076);
   - in PR 20538 a reviewer warned that `forms.BooleanField.to_python()` behaves differently, and that exact difference shipped as #37263 (DJ-050).
   
   This is the strongest field evidence we have for #39 and #42. Good human reviewers do the test-the-test step by hand, and a test added to satisfy the comment didn't close the class.
2. **Security fixes cause regressions too.** Three advisory fixes shipped user-facing regressions in the window: wordwrap DJ-039, IPv6 validation DJ-062, and the redirect length cap DJ-073. A rewrite of header parsing onto the stdlib was reverted in 2025 for speed (DJ-082). It came back in 2026 as the fix for CVE-2026-84429 (DJ-088). #28 applies to security work, and so does L4: the hand-rolled parser was the vulnerable one.
3. **#43 is broader than its wording.** "One PC, many people" caught all six shared-cache advisories once the response cache is read as the shared machine. The Ask ("what is keyed by machine, address or browser, and should it be keyed by person?") works unchanged if "machine" becomes "anything shared". Consider widening the title.
4. **The human reference's edge-path list (§2 item 2: None, empty, zero, second use) isn't AI-specific.** Django's human authors miss it at the same rate: D3, D6 and the iterator candidate. On the other hand, nothing in 132 rows was about proportion or bloat (§2 item 4). Django reviewers often ask for simpler code, but that never showed up as a defect. This agrees with §3 ("measurement says verbosity and scope creep dominate, architecture about 10%"): bloat costs review time, not correctness.
5. **AI is now visible inside Django's own process.**
   - The PR template has required an AI-assistance disclosure since about mid-2025. Of the 93 PRs I checked, 22 ticked "AI tools were used" and 9 ticked "no AI". The other 62 predate the template or left it blank.
   - Reviewers now quote model findings. In PR 16012 an AI review's security point, a forged `select_across` POST, was confirmed by a human (DJ-034). In PR 22039 a reviewer prompted a model, which found the behaviour change that later shipped as a regression. Review comments on 11 PRs mention using a model. Copilot bot comments appear in at least two (20540 and 20763; neither landed).
   - **Authorship overrides used:** DJ-016 is `ai`, because its disclosure says Claude Code drafted the implementation, tests and docs. That is the only Django row that feeds the check order: it added 5 to #6, which stays first. Seven rows are `mixed`, where AI was used to understand, research or review: DJ-012, DJ-014, DJ-015, DJ-017, DJ-019, DJ-021, DJ-033. None of the PRs that *caused* the 42 regressions declared AI use.
6. **Formal "changes requested" is almost unused.** The MINING.md query (`review:changes_requested`) returned one PR in two years. Django reviewers comment and the merger commits by hand, so most landed PRs show as "not merged" on GitHub. This affects the recipe in MINING.md §4.1; see section 7.

## 7. Couldn't check
- **Issues (§4.5):** Django tracks bugs in Trac, not GitHub issues. Its GitHub labels carry no regression or crash label, so no issue-label rows were taken. One Trac ticket (36572) was read as CSV for context. The 20% revert-and-issue share is 9 reverts (10%).
- **Reviews:** only inline review comments (`pulls/comments`, 12,979 in the window) were scanned. PR conversation comments and review summary bodies weren't. Candidates were picked by defect keywords plus an author acknowledgement, so catches phrased differently are missed.
- **Merged PRs only:** I kept PRs GitHub marks as merged. Many PRs Django landed by hand show as unmerged and were dropped, along with several strong unmerged catches: a mutated queryset, an async savepoint losing writes, a same-name upload race.
- **Recipe gap in MINING.md §4.1:** for Django-style repos, the reviews step needs "acknowledged inline comments on landed PRs" instead of `review:changes_requested`. I didn't edit MINING.md, because it isn't mine to commit.
- **Unreleased notes:** the 5.2.19, 6.0.10 and 6.1.3 notes (dated 2026-11-03) are on main but not yet released. DJ-067 (#37463) and DJ-076 (#37450) come from fixes in that unreleased batch.
