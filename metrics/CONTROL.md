# Control runs

Does the Dev Instincts method find more real bugs, and make fewer false claims, than the same model with no method? On each repo, arm A (the `instinct-reviewer` in file mode) and arm B (a plain Claude Code session) review the same commit, and a blind judge rules on every claim. The protocol is `testing/CONTROL.md` (Garrett's decision, 2026-11-02), fixed before any arm B or judge ran; `tools/control.py` shuffles, scores and checks the sessions.

**Hypotheses (Garrett, 2026-11-02, before the data):** A finds more judge-confirmed findings per hour than B. A has fewer judge-refuted claims per finding than B. The null (added 2026-11-02, before the data): the arms don't differ beyond the noise floor.

**Claims (Garrett, 2026-11-02):** none before 3 repos have their judge's verdicts. Every repo is reported here, including where B does better. Amended the same day (`testing/CONTROL.md` §14): 3 repos are a description only; the test is at 5, a sign test on direction, and no claim of significance comes before it.

**Repos with verdicts (2026-11-05): 1 of 5; 3 is the descriptive checkpoint.**

Each measure cell reads A / B, as `testing/CONTROL.md` §12 defines it: *confirmed* counts distinct bugs (the judge's groups); *weighted* uses the judge's severity (data-loss 4, security 4, wrong-result 3, crash 3, stuck 2, process 1, cosmetic 1); *minutes* run from the later of the prompt and the clone to the report's last write; *tokens* are output tokens, from the session's transcript. The two headline columns stay blank until the judge has ruled. On the first repo each arm runs twice (§12.1), so a cell reads A's run 1, run 2 / B's run 1, run 2; the judge runs twice too, and a third time on the claims the two disagree on (§10.1).
